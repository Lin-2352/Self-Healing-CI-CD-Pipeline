# Setup

This page gets the n8n healer running on a Windows PC and takes it through a first test. When a GitHub Actions run fails on `main`, a job in `.github/workflows/demo-ci.yml` posts to an n8n webhook. The workflow in `n8n/self_healing_pipeline.json` (26 nodes) fetches the job log and the changed files, asks the Qwen3.8-27B model on Kaggle for a fix, and opens a pull request on an `ai-fix-...` branch.

To run the workflow on n8n Cloud instead of a local n8n, read [cloud-n8n.md](cloud-n8n.md) after the Kaggle and GitHub steps here. To run `ci-heal-backend` instead of n8n, use [its README](../../ci-heal-backend/README.md) and [launcher.md](launcher.md). Run one healer per repository, because both react to the same failed run.

## What is in the repository

| Path | What it is |
|---|---|
| `demo-app/` | The Express app the pipeline heals. `test.js` boots the server and requests `/`. `test/api.test.js` checks four routes in `src/app.js`. `npm test` runs both. |
| `.github/workflows/demo-ci.yml` | CI for `demo-app/`, plus the job that calls n8n when a build fails. |
| `n8n/self_healing_pipeline.json` | The workflow. Generated by `tools/gen_n8n.py` from the code in `tools/nodes/*.js`. |
| `tools/golive/` | Scripts that start n8n, import the workflow and credentials, and tell the workflow where the model is. |
| `kaggle/` | The model endpoint notebook and the tools that push it and read its URL. |
| `launcher/` | Double-click `.bat` files that call the scripts above. See [launcher.md](launcher.md). |

## Prerequisites

1. Windows with PowerShell, Python 3.10 or newer, and Node.js with npm (`kaggle/README.md` lists the Python version; CI uses Node 20).
2. The GitHub CLI, signed in once with `gh auth login`. `tools/golive/n8n_import.py` reads your token with `gh auth token`, and `tools/golive/up.py` sets the repository secret with `gh secret set`.
3. The Kaggle command line, signed in with an API token in `%USERPROFILE%\.kaggle\kaggle.json` (`kaggle/README.md`, section Prerequisites). The token stays outside the repository.
4. `cloudflared.exe` placed at `%LOCALAPPDATA%\selfheal-n8n\bin\cloudflared.exe`. `up.py` starts a quick tunnel with it so GitHub can reach your PC.
5. A GitHub repository that holds this code, so that `.github/workflows/demo-ci.yml` runs. The repository that `up.py` writes its secret to is the `REPO` constant at the top of `tools/golive/up.py`. Change it to your own `owner/name`.

## Where secrets live

Everything that changes at runtime sits in `%LOCALAPPDATA%\selfheal-n8n`, outside the repository. `.gitignore` also blocks `secrets.json`, `*.env` and `_creds_plain.json` as a second guard.

| File or folder | Written by | Contents |
|---|---|---|
| `secrets.json` | You, once | A JSON object with two string fields: `encryption_key` (any string you choose, used as `N8N_ENCRYPTION_KEY`) and `webhook_secret` (the shared secret for the webhooks). |
| `qwen_url.txt` | `kaggle/tools/watch_deploy.py` | The current model URL. |
| `app\` | You, in the next section | The n8n 1.x install. |
| `.n8n\`, `n8n.out`, `n8n.err`, `*.pid`, `tunnel_url.txt` | n8n and `up.py` | n8n's database, logs and process ids. |

No script creates `secrets.json`. Write it yourself, and pick a long random value for `webhook_secret`. The same value goes into three places: this file, the n8n credential named `N8N Webhook Secret`, and the GitHub secret `N8N_WEBHOOK_SECRET`. The local import creates the n8n credential from this file for you.

## Install n8n 1.x

Install n8n 1.x only. Version 2.x never registers the webhook, so the workflow would import and activate but never receive a request (`tools/n8n_rig/README.md`, Setup).

1. Open PowerShell and create the folder: `New-Item -ItemType Directory -Force "$env:LOCALAPPDATA\selfheal-n8n\app"`.
2. Run `cd "$env:LOCALAPPDATA\selfheal-n8n\app"`, then `npm install n8n@^1`. It takes about 6 minutes. The rig README records 1.123.81 as the last version used.

Run this from PowerShell. The same install from Git Bash fails in npm's postinstall step on the development PC (`tools/n8n_rig/README.md`).

`up.py` and `n8n_import.py` start n8n with `N8N_USER_MANAGEMENT_DISABLED=true`, so a fresh local n8n opens without an owner account.

## Start the model

1. Run `launcher\start\1_start_model_on_kaggle.bat`. It checks that no project kernel is running, builds and pushes the endpoint notebook, watches the boot for about 4 minutes, and then tries to post the URL to the cloud n8n workflow. If you only use a local n8n, the last step may report that it could not update n8n. The model is still up.
2. Confirm with `launcher\start\show_model_info.bat`. It prints the model URL, the endpoint key, and whether the model answers.

The URL changes on every boot. Stop the session when you are finished (`launcher\end\stop_model_on_kaggle.bat`), because it uses Kaggle GPU quota while it runs.

## Credentials

The workflow's nodes refer to three credentials by id and name.

| Credential | Type | Value |
|---|---|---|
| `N8N Webhook Secret` | Header Auth, header name `X-Webhook-Secret` | `webhook_secret` from `secrets.json` |
| `GitHub PAT` | Bearer Auth | A GitHub token that can read the repository's Actions logs and contents and write branches and pull requests |
| `Qwen3.8 Endpoint Key` | Bearer Auth | The endpoint key that `show_model_info.bat` prints |

On a local n8n you do not create these by hand. `tools/golive/n8n_import.py` writes all three from `secrets.json`, your `gh auth token`, and the endpoint key, imports them, and deletes the temporary plaintext file. The `GitHub PAT` credential therefore holds your `gh` token. For n8n Cloud you create them in the n8n interface, as described in [cloud-n8n.md](cloud-n8n.md).

## Load the workflow and start n8n

1. Run `launcher\start\2a_load_workflow_into_n8n.bat`. It stops any running n8n, imports the credentials and `n8n/self_healing_pipeline.json` with id `selfHealPipeline01`, and activates the workflow. Run it again after every new Kaggle session.
2. Run `launcher\start\3a_start_n8n_live.bat`. `up.py` starts n8n on port 5678, starts a Cloudflare quick tunnel, and sets the repository secret `N8N_WEBHOOK_URL` to the tunnel address plus `/webhook/github-failure`. It first probes the webhook with a wrong secret and waits for a 401 or 403, which shows the webhook is registered and guarded.

To look at the workflow without a tunnel or any change on GitHub, run `launcher\start\start_n8n_local_only.bat` (`up.py --local`) and open http://localhost:5678.

### How the model URL reaches the workflow

The node `Get Model URL` runs before every model call. It uses the address stored by the `Set Model URL` webhook (`/webhook/set-qwen-url`, handled by `Store Model URL`), and falls back to the n8n variable `QWEN_BASE_URL` if nothing was stored (`tools/nodes/get_model_url.js`). Local n8n has no `$vars`, so `n8n_import.py` writes the contents of `qwen_url.txt` into the imported copy of `Get Model URL` as the fallback. The file in the repository is left unchanged.

## GitHub secrets

In the repository, under Settings, Secrets and variables, Actions, two secrets are read by `demo-ci.yml`. Names are case-sensitive.

| Secret | Value | Set by |
|---|---|---|
| `N8N_WEBHOOK_URL` | The production webhook URL | `up.py` for a local n8n; by hand for n8n Cloud |
| `N8N_WEBHOOK_SECRET` | The same string as `webhook_secret` | You, for example `gh secret set N8N_WEBHOOK_SECRET --repo <owner>/<repo>` |

`up.py` leaves `N8N_WEBHOOK_SECRET` alone, so set it once yourself. The GitHub token for the pull requests lives in n8n, not in GitHub secrets.

## How the notify job works

`demo-ci.yml` has two jobs.

1. `build-and-test` runs in `demo-app/` on pushes and pull requests to `main` that touch `demo-app/**`. The `Run tests` step runs `npm test` and turns the exit code into an output named `failure_kind`: `none` for 0, `infra` for 75 (port in use or a similar environment problem, set by `test.js`), `code` for anything else.
2. `notify-n8n-on-failure` waits for the first job. It runs only when the first job failed, `failure_kind` is `code`, and either the event is a push or the pull request branch starts with `ai-fix-`. A pull request from a person never starts it.

Inside the notify job, the step `Decide - heal, retry, or give up` sets the branch, commit and attempt. On a push the attempt is 0. On an `ai-fix-` pull request it reads the `Heal-Attempt: N` trailer from the head commit message. With no trailer, a person pushed to the branch and the job does nothing. At `MAX_ATTEMPTS` (3) it comments on the pull request that it has stopped. Otherwise the step `Trigger n8n webhook` posts JSON (`run_id`, `repo`, `branch`, `commit`, `actor`, `failure_kind`, `attempt`, `pr_number`) to `N8N_WEBHOOK_URL` with the header `X-Webhook-Secret`. If the request fails, the job prints a warning and does not fail, so a stopped healer does not turn an unrelated commit red.

The workflow's `Build AI Prompt` node refuses a payload whose `failure_kind` is not `code`, since the webhook URL is public.

## First test

1. Check the app on its own: `cd demo-app`, `npm install`, `npm test`. The output ends with `smoke test passed` and `api test passed (4 routes)`.
2. Make sure the model answers (`show_model_info.bat`) and that `3a_start_n8n_live.bat` finished without an error.
3. On `main`, break something in `demo-app/`. For example, in `demo-app/src/format.js` change `sum: a + b` to `sum: a - b`, so the `/sum?a=2&b=3` check in `demo-app/test/api.test.js` fails. Commit and push.
4. Open the Actions tab. `build-and-test` fails and `notify-n8n-on-failure` runs.
5. Watch the executions in n8n at http://localhost:5678, or run `python tools/golive/exec_stats.py` to list recent executions from the local n8n database.
6. An `ai-fix-...` pull request should appear. In earlier live runs it took about 40 seconds from the push (`docs/results/GOLIVE_RESULTS.md`). The pull request gets its own CI run through the `pull_request` trigger.

When you finish, run `launcher\end\stop_everything.bat`. The repository secret keeps the dead tunnel address, and the notify job only warns until the next `3a_start_n8n_live.bat`.

## Problems seen so far

| Symptom | Cause |
|---|---|
| The webhook answers 404 right after n8n starts | n8n answers `/healthz` before it activates workflows. `up.py` waits on the webhook probe instead. |
| The workflow imports but never triggers | n8n 2.x is installed. Reinstall 1.x. |
| `npm install n8n@^1` fails and rolls back | It was run from Git Bash. Run it from PowerShell. |
| A new tunnel address does not resolve for a minute | The probe in `up.py` resolves it through DNS-over-HTTPS, as GitHub's runners would, to avoid the Windows resolver caching a failure. |
