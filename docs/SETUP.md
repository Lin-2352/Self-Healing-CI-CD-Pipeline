# Self-healing CI/CD pipeline: build and setup guide

Follows the video (`youtube.com/watch?v=vj68el9hRvU`) but replaces the OpenAI node with a
**self-hosted Qwen3.8-27B** endpoint. Everything downstream of the model call is unchanged.

```
GitHub Actions fails
   -> notify-n8n-on-failure job (if: failure())  ->  curl POST to n8n webhook
   -> n8n: fetch job logs -> fetch changed files -> fetch raw source
   -> Build AI Prompt (Code)  ->  Qwen3.8 endpoint  ->  Extract AI Response (Code)
   -> create branch -> get file SHA -> push fixed file -> open PR
```

## What's in this repo

| path | what |
|---|---|
| `app/` | the demo Node/Express project the pipeline heals (its own repository, `Lin-2352/self-healing-cicd-demo`, cloned here) |
| `app/index.js` | trivial entry point |
| `app/test.js` | smoke test — boots Express on :5000, GETs itself, exits non-zero on failure |
| `app/package.json` | `test` + `build` scripts |
| `app/.github/workflows/main.yml` | CI pipeline + the failure webhook job |
| `n8n/self_healing_pipeline.json` | **importable** n8n workflow (20 nodes, generated by `tools/gen_n8n.py`) |
| `docs/research/QWEN38_SWEEP_RESULTS.md` | model benchmark results |
| `docs/research/KAGGLE_ENV_MEASURED.md` | Kaggle specs, CUDA build fix, accelerator gotcha |

Verified locally: `npm test` -> `smoke test passed`, exit 0.

## 1. GitHub repo

```bash
cd app
git init && git add . && git commit -m "first"
git branch -M main
git remote add origin https://github.com/<you>/<repo>.git
git push -u origin main
```

## 2. Personal Access Token

GitHub → Settings → Developer settings → Personal access tokens → **Tokens (classic)** →
Generate new token (classic). Scopes: **`repo`**, **`workflow`**, **`admin:repo_hook`**.
Copy it once — GitHub will not show it again.

## 3. Repo secrets

Repo → Settings → Secrets and variables → **Actions** → New repository secret.
Names are case-sensitive and must match `main.yml` exactly:

| secret | value |
|---|---|
| `N8N_WEBHOOK_URL` | your n8n webhook URL (Test URL while building, Production URL at the end) |
| `N8N_WEBHOOK_SECRET` | any strong string; the same value goes in the n8n Header Auth credential |

> The video also stores `GH_TOKEN` as a repo secret. This build doesn't need it there — the PAT
> lives in n8n, which is what actually calls the GitHub API. Keep it out of Actions.

## 5. n8n

1. **Import** `n8n/self_healing_pipeline.json` (Workflows → ⋯ → Import from File).
2. Create the three credentials the nodes reference:
   - **Header Auth** "N8N Webhook Secret" — name `X-Webhook-Secret`, value = your `N8N_WEBHOOK_SECRET`
   - **Bearer Auth** "GitHub PAT" — the classic PAT from step 2
   - **Bearer Auth** "Qwen3.8 Endpoint Key" — whatever you passed to `--api-key`
3. Set a workflow **variable** `QWEN_BASE_URL` = `https://<sub>.trycloudflare.com`
   (Settings → Variables). The model node reads `{{ $vars.QWEN_BASE_URL }}`, so when the tunnel
   URL changes you edit one variable instead of the node.
4. Copy the webhook's **Test URL** into the `N8N_WEBHOOK_URL` repo secret while developing.

## 6. Break it on purpose

In `app/test.js`, delete the line `const app = express();`, then:

```bash
git add . && git commit -m "break it" && git push
```

Actions runs → `npm test` fails with `ReferenceError: app is not defined` → the
`notify-n8n-on-failure` job fires the webhook → n8n analyses and opens a PR.

## 7. Production

Switch the webhook node from Test URL to **Production URL**, hit **Publish**, and update the
`N8N_WEBHOOK_URL` secret to the production URL.

## Notes specific to using Qwen3.8 instead of OpenAI

- **Strip the reasoning trace.** Qwen3.8 is hybrid-reasoning; the `Extract AI Response` node
  removes `<think>…</think>` (including an unclosed trace) before `JSON.parse`. Verified against
  a reply containing both a think block and markdown fences.
- **Thinking is disabled for this call** via `chat_template_kwargs.enable_thinking:false`.
  Measured on the eval: it did not hurt fix quality and avoids burning the token budget.
- **The request body is built in the Code node**, not interpolated into the HTTP node's JSON
  body. Interpolating a multi-line prompt into a JSON string breaks escaping — this avoids it.
- **Kaggle is not a durable host**: 30 GPU-h/week per account and sessions expire, and the
  quick-tunnel URL changes on every restart. Fine for building and testing. For always-on, use a
  named Cloudflare tunnel or a hosted OpenAI-compatible provider — only `QWEN_BASE_URL` changes.

## Infra failures never reach the model

Verification found that a busy port made `test.js` die with an *unhandled* `'error'`
event. CI still failed (good) but the pipeline would then hand the model an
`EADDRINUSE` stack trace and ask it to "fix the code" - there is nothing to fix, so it
would invent a patch and open a bogus PR. Three layers now prevent that:

**1. `test.js` classifies its own failures via exit code**

| exit | meaning | pipeline reaction |
|---|---|---|
| `0` | healthy | nothing |
| `1` | `CODE_FAILURE` - the app is genuinely broken | self-heal runs |
| `75` | `INFRA_FAILURE` - port taken, DNS, runner problem (`EX_TEMPFAIL`) | CI fails, self-heal **skipped** |

A busy port now prints one clean line instead of a stack trace:

```
INFRA_FAILURE: port 5000 is already in use - environment problem, not a code bug
```

`PORT` is also honoured via env var, so a runner can move the smoke test off 5000.

**2. `main.yml` gates the webhook on the failure kind**

The `Run tests` step maps the exit code to a job output, and the notify job requires it:

```yaml
if: failure() && needs.build-and-test.outputs.failure_kind == 'code'
```

Plain `failure()` would also fire for infrastructure problems. The payload now carries
`failure_kind` too.

**3. The n8n `Build AI Prompt` node refuses anything that is not a code bug**

The webhook URL is public, so the node re-checks and throws rather than calling the model:

```
Refusing to run: failure_kind="infra" is not a code bug.
Nothing in the source to fix, so no model call and no PR.
```

A payload with no `failure_kind` still proceeds, so older callers keep working.

> Note: an unrecognised non-zero exit (e.g. `137`, OOM-kill) classifies as `code`. That
> fails toward attempting a fix, which is the safer default here - but if OOM-kills become
> common on your runner, add `137` to the infra branch in `main.yml`.
