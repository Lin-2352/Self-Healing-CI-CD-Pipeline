Model bake-off: is there a better Qwen3.8 for this?

Four Qwen3.8-27B builds with an MTP head, each run on the same production server flags and the same 17 heal cases (5 control, 6 hard, 6 multi-file, two reps). Fast = thinking off, as on a first heal; thinking = as on a retry. The rule was fixed before the data: pass every control, then rank by fast heals, and switch only for 3 or more extra heals at 95% of the speed or better.

__BAKEOFF__

All four heal the same 14 of 24 hard calls on the first try, so a different model of this size cannot raise first-pass accuracy. The extra heals come from thinking depth: the fine-tunes think 4 to 6 times less and heal fewer retries. One case, signature_changed_caller_not, fails for every model: the fix belongs in a caller file the model is never shown.

Phase 6: bugs that span files

The demo app now has src/ modules and an API test, so a bug can live in a different file from the one that fails. A new step picks which files the model sees: files in the CI stack trace first, then the commit's changed code files, up to 3. Six cases cover a helper that throws deep in the stack, a non-code first change, a bug in the second changed file, a latent bug reachable only through the stack trace, a wrong import path, and a changed signature whose caller was not updated.

__MULTI__

The fast first pass reached a file that can fix the bug in 15 of 18 calls, but twice it fixed the crash instead of matching what the test expects. A retry, which sees the new "expected / got" log, fixed all 6 of those. The 3 misses are one case: the fix belongs in a caller that was never shown. With no stack trace, nothing points to it, so no PR opens and the healer comments instead. By the rule set before the run (the fast pass must heal at least 12 of 18), multi-file healing is not yet declared shipped. Details: docs/results/MULTIFILE_EVAL.md.

Known limits

  • Retries can anchor on a wrong first fix. On callback_arity the first fix kept the wrong callback signature, and the retries chased the new error text instead of revisiting it. The next step is a neutral retry prompt, tested offline first.
  • A retry that produces no commit is silent. Fixed (see the top of the page): the model call is streamed, and any heal that ends without a fix posts a comment explaining why.
  • A failure after the fix is pushed is still not commented. If Create Branch, Push Fix File or Open Pull Request errors, the n8n run fails without a comment. These GitHub calls have not failed in any live round.
  • A first fix that does not parse opens no PR, so it never gets a retry.
  • Small test surface. All 11 bugs live in one ~50-line Node/Express smoke test. This measures the pipeline's bug types, not general coding ability.
  • Kaggle queueing. The eval kernel waited about 2.5 hours for a free T4×2 before it started.
